Agents vs Wall Street

Forecaster

Nine lenses read one evidence corpus blind to each other; every claim is quoted and matched back to the document it came from, and a single deep-tier judge weighs what survives by materiality rather than by vote.

Agent name: Forecaster

Team: Utkarsh Malhotra (solo)

Build style and harness: coding harness — Claude Code, unmodified. The agent itself is a headless Python pipeline run by one command.

Models: claude-opus-5 (deep tier, the judge), claude-sonnet-5 (mid tier, lenses / challenge / narrative), claude-haiku-4-5 (cheap tier, extraction, scanners, research scout, comparability)

How it works

One command runs four companies end to end. Each company walks the same stages in a fixed order, written out top to bottom in forecaster/run.py with no registry and no dispatch loop, so the whole data flow can be read aloud while somebody watches over your shoulder. Every node has a stable ID (J1–J7 for sources, U1–U26 for the pipeline) defined once in forecaster/nodes.py; those IDs appear in module names, event names and log lines, so a line in the event tape names the node that produced it.

ticker ──► A  sources        J1 frozen filing corpus · J2 consensus · J3 news + web
       │                     J5 universe · J6 macro (FRED) · J7 sponsor templates
       ├──► B  acquire       U1 metric extractor   U4 guidance extractor   (cheap)
       │                     U5 research scout     U8/U9 call + perception scanners
       ├──► C  evidence      U10 one byte-identical store; claim = source + quote
       ├──► D  income model  U11 medians + scaled MAD, projection, reproduction error
       ├──► E  analyse       U12 mechanical (no model call) + eight lenses (mid),
       │                     blind to each other, one call each for all 3 metrics
       ├──► V1 reconcile     U21 deterministic gate: every citation ID must exist,
       │                     every quote must string-match. A lens that fails is
       │                     dropped whole. All lenses dropped ⇒ the run raises.
       ├──► F  challenge     U22 each surviving view argued for, then argued against
       ├──► G  judge         U23 ONE deep-tier call ⇒ p10/p25/p50/p75/p90 per metric
       ├──► V2 comparability U24 acquisition · accounting change · 53rd week ·
       │                     withdrawn guidance — do the historical priors still hold?
       ├──► H  position      U26 deterministic; consensus bus terminates here
       └──► I  output        results.json ⇒ xlsx writer ⇒ shape checker ⇒ submission/

The tiers are assigned once, in forecaster/agents/tiers.py: cheap for retrieval and extraction, mid for the lenses, the challenge and the narrative, deep for the judge alone — one deep call per company, enforced by a test. The client is our own urllib wrapper over the Messages API (there is no working pip on the build machine), doing five things and only five: force a schema and validate before returning, cache on a content hash on disk, enforce a hard cost ceiling, handle prompt caching of the shared corpus, and retry on rate limits and 5xx only.

Research and financial reasoning

Finding information. Five source adapters sit behind one priority chain. The organisers' frozen corpus (1,139 documents, frozen 2026-08-14) supplies filings, transcripts and slides and is the only source of historical financials, because a number that traces to a document a judge can open is worth more than one that traces to an API response they cannot see. On top of that: an agent-driven industry research scout that proposes searches, sees the titles that came back and asks for what is still missing — a fixed query list cannot notice that every result came from the same trade magazine; date-bounded news, with the upper bound enforced at the API rather than filtered afterwards, so material published after the lock date cannot enter the result set at all; FRED macro with realtime_start pinned to the lock date, so the series comes back as it stood then rather than as later revised; and analyst consensus, which is rendered beside every forecast as the Street number and never feeds it.

Everything retrieved from the web is written into the run directory as a document, so a lens citing research is quoting text that exists on disk and the gate can string-match it exactly as it matches a quote from an 8-K.

Metrics and units. The metric label, units and period header come from the sponsor templates and challenge/companies.json — the agent never invents them. Every extracted value is typed against the metric it is offered for, and two guards reject values that merely mention the right words: a percentage offered for a money or per-share metric is discarded, and a post-exceptional value offered for a pre-exceptional line is discarded. A third guard rejects a figure covering a different period length than the one we owe — a half-year figure for a full-year metric, a full-year figure for a quarterly one. Each discard is recorded on the metric rather than dropped silently. Consensus revenue arrives in absolute currency and is converted to millions in exactly one place, because getting that direction wrong is a 1,000,000× error that still looks like a plausible number on a sheet.

Conflicting evidence. Four mechanisms, in order. First, the evidence store splits verification three ways — prose (a human wrote it, a model quoted it, the quote must be found), structured (the quote is the tagged fact itself, rendered by an adapter from a typed response) and derived (something the pipeline computed, deliberately in neither set, justified by the claims underneath it). News is deliberately not evidence at all: we hold a snippet rather than the article, coverage published days before a print is preview and positioning, and no lens may cite it. Second, the challenge stage argues every surviving case into its strongest honest form and then argues against it hard, and the gap between stated and surviving confidence reaches the judge as a discount on that view's weight — never as a vote. Third, the spread between lenses is measured as a coefficient of variation per metric, with abstentions counted separately rather than folded in. Fourth, the comparability gate asks whether this period can be compared with the company's own history at all; when it fires, the historical priors the system runs on have stopped applying, and that is carried forward rather than noted and forgotten.

Turning research into a forecast. The deterministic income model — an income statement, not three, because none of the twelve metrics touches a balance-sheet or cash-flow line — builds history as filed, a ratio base of medians with the scaled MAD beside each, a projection, and a reproduction check that re-projects each recent reported period using only the statistics as they stood before it. That measured error is the model's structural bias and it goes to the judge with the projection, because a model should state its own error before anyone trusts it. The judge then receives every surviving view with its reasoning, its confidence after being argued against, what would change its mind, the lenses that produced nothing and why, what one sigma of each metric's own history is worth, and the disagreement between views — and returns five named quantile fields per metric. Named float fields rather than a free-form object, because a free-form object comes back empty with the numbers written into the prose, which validates fine and carries no forecast.

Important design choices

Positioning toward consensus is switched off — by configuration, not by deletion

Accuracy here is our miss divided by the Street's miss, capped at 5.0 and averaged over twelve metrics. A forecast shrunk hard onto consensus inherits the Street's error and scores a ratio of about 1.0 by construction: safe, and unable to place. Submitting our own estimate is the only way to score below 1.0, and it accepts a wider spread of outcomes in exchange. This deliberately reverses the specification's own instinct, so it is written down rather than left to be inferred from a lambda that happens to equal 1. What did not change: consensus is still acquired, still carried on its own bus, and every regime condition it would have triggered is still measured and reported — the run states, for each metric, the lambda that would have applied. Rejected alternative: deleting the positioning stage, which would have made the decision invisible and unmeasurable.

The consensus bus is structural, not a diagram label

It is tapped once where consensus enters, carried untouched, constructed in the orchestrator and handed to exactly one stage. It exposes no method a reasoning stage could write to, and no lens or judge signature takes it. A test asserts both properties, so lookahead through consensus is prevented by the shape of the code rather than by a promise in a prompt. The same instinct governs the lenses: there is no parameter through which one lens's view could reach another, and a change that would create one is rejected on that basis alone.

A lens that fabricates one citation is dropped whole

Not the offending claim — the entire view. A lens that invented one citation has told you something about the rest of its reasoning, and keeping its surviving claims means keeping the parts of an argument whose author you have just stopped trusting. The cost is real: Hays lost two of nine lenses this way on the final run. The alternative — dropping the bad claim and keeping the rest — was rejected because it makes fabrication cheap.

One deep-tier call, spent on the judge

The judge is the highest-leverage decision in the system, so it is the only call on the deep tier and exactly one is allowed per run (asserted by a test). The narrative agent is deliberately mid-tier: prose written from a settled answer is not where the leverage is, and spending the expensive tier there would take the call away from the decision that actually moves the number.

Degrade loudly, never silently

If the judge call fails, the fallback is the median of surviving views and it labels itself degraded on every metric. If the judge returns crossed quantiles, they are sorted and the correction is recorded — accepting them silently and sorting them silently are both ways of hiding that it happened. If a metric has no judged distribution, it falls back to the model projection and says so. A blank scores the maximum 5.0 penalty, so the system always ships a number; it just never ships one that looks better than it is.

The newest healthy run wins, not the newest run

This exists because of a specific failure during the build: the API ran out of credit mid-run, Deere's scout, all three scanners and eight of its nine lenses failed, the pipeline correctly degraded and produced numbers anyway — and those numbers then overwrote a healthy run's numbers, because the writer took the most recent run rather than the best one. Health is now judged explicitly (stage reached, surviving lens floor of four, no failed lenses, judge not degraded, no metric equal to consensus), and when nothing is healthy the writer says so loudly rather than quietly shipping the wreckage.

Standard library only, and one command with no install step

No pip works on the build machine, so the Anthropic client, schema validator, tier router, disk cache and fan-out runner are written here over urllib. A constraint rather than a preference, but it has one real benefit at 17:30: the final run has no dependency install that can fail. Node is used only for the workbook writing and the shape checks, where SheetJS was already in the starter.

Two things built and then taken out

SEC XBRL adapters work and are out of the priority chain on purpose, so every historical number traces to a document in this repository. And an earlier build computed a baseline — consensus times the company's shrunk historical beat — which was removed: consensus is the bar this event actually scores against, and a second invented bar beside it was one more number a reader had to interpret before reaching the comparison that matters.

Checks and tests

What the running system catches

  • Fabricated quotes. Twice. At extraction, every quote is string-matched back against the document it was attributed to — this is the only stage that can catch a guidance range assembled from two different sentences, which reads beautifully and is not what the company said. Then again at the V1 gate, deterministically: nothing that can hallucinate decides which hallucinations survive.
  • Invented citation IDs. Every cited ID must already exist in the evidence store. An estimate with no citation at all is also a drop — an uncited estimate is unfalsifiable.
  • Total collapse. If every lens is dropped, the run raises rather than emitting a number nothing supports.
  • Bad units and mixed kinds. Percentage-for-money, post-exceptional-for-pre-exceptional and wrong-period-length values are rejected before they can reach a median, each rejection recorded on the metric.
  • Implausible distributions. Crossed quantiles are sorted and flagged; disagreement is measured per metric; the comparability gate flags periods where the priors have broken.
  • Invented figures in the write-up. Every number in the narrative agent's prose is pulled out and checked against the set of figures the pipeline actually produced. Prose carrying an invented figure is rejected rather than printed.
  • Malformed model responses. The schema validator never coerces, never defaults a missing field and never accepts a string where a float was declared. Schema errors fail fast rather than retrying — retrying malformed structured output mostly reproduces it and bills you twice. Rate limits and 5xx are retried.
  • Cost. A hard ceiling raises before the call that would breach it, and every call's tokens, cache hits and dollars are logged.
  • Malformed workbooks. The writer patches the organisers' templates in place and refuses to write a non-finite value, a value count that does not match the metric count, a template that no longer matches companies.json, or one whose fiscal-period header does not match the spec. The checker then re-opens each file on disk and verifies the Metric / Units / period header, the exact metric labels and units, and that every forecast cell holds a finite number.
  • Whole-company failure. Each company is retried once — the retry is nearly free because every repeated model call is served from the disk cache, so what is really being retried is the transport. One company failing cannot cost the other three their numbers.

What was tested, and what happened

106 automated tests, all passing — 93 Python (py -m unittest discover -s tests -t .) and 13 Node (npm test), verified at the time of writing. Beyond ordinary unit coverage, a suite of structural invariants asserts the architecture rather than the outputs: no lens signature can accept another lens's view; the corpus a lens reads contains no lens output; only the positioning stage accepts the consensus bus; the bus exposes nothing writable; only the judge runs on the deep tier; every lens dropped raises rather than forecasting; the results file is never observed half-written; every prompt file has a node, every agent node has a prompt, and every prompt declares a version.

Three defects were found by these checks during the build, each fixed in its own commit:

  • Hays net fees were contaminated. A results release gives net fees in pounds and net fee growth as a percentage in the same breath; both mention net fees, both matched on label, and fourteen of sixteen observations in the series were percentage declines sitting in a series measured in millions. A median across two kinds of thing is a median of nothing, and everything downstream inherited it. This is what the kind and period-length guards now exist for.
  • The judge's metrics were silently unmatched. The judge is given each metric label with its units beside it and sometimes echoes the pair back as one string; an exact comparison found nothing and every metric read as unjudged. Label matching is now normalised, with a containment fallback.
  • A degraded run overwrote a healthy one after the API ran out of credit — the failure that produced the run-health check described above.

The final run itself is verified end to end and reports an exit code that means something: 0 = four workbooks written, verified, and every number forecast in this run; 1 = a workbook failed verification, do not upload; 2 = the workbooks are the right shape but at least one company carried forward previous numbers rather than forecasting today. The last clean run exited 0 with all four files PASS.

Reproducing the run

Install and configure. Python 3.14 (standard library only — nothing to install) and Node.js with npm install for the two npm packages the starter already listed. Three keys in .env or the environment: ANTHROPIC_API_KEY (required), EXA_API_KEY (news and industry research) and FRED_API_KEY (macro). Missing optional keys degrade that source and are recorded on the run rather than crashing it.

How the company and metric specification enters. Nothing about the four companies is hardcoded in Python. challenge/companies.json supplies the tickers, the fiscal periods, the twelve metric labels, their units and the output filenames; the organisers' workbook templates supply the period header; and config/forecaster.json holds the run parameters — as_of, the corpus freeze date, the source priority chain, the per-company research angles and macro series, the tier-to-model mapping, the cost ceiling and the positioning switch. Adding a fifth company means editing JSON, not Python.

Remaining human input. None during the run. A human reads the log, sanity-checks the four numbers, and uploads the files by hand — the rules require manual upload, and the agent does not post to OpenStocks.

Known weaknesses

  • Dropping a lens whole is expensive. Two Hays lenses died on two failed quote matches on the final run, taking their good claims with them. The trade is deliberate, but a lens that mis-transcribes one em dash is treated exactly like one that fabricates, and I would separate those cases next.
  • The extraction drops are not audited. Between 43 and 144 candidate values per company were discarded by the guards. Spot checks say they are overwhelmingly correct rejections, but nothing verifies that a right value was never thrown away with them.
  • Lambda's base is asserted, not fitted. The regression that would measure it needs the Street bar as it stood at past quarters, and no source available here publishes consensus history. Positioning is switched off for this run, so it does not touch the submitted numbers — but the machinery would need that measurement before it should ever be switched on.
  • Hays has no consensus coverage at all in the market adapter, so three of the twelve numbers have no Street comparison to render, and Hays is also the name where the corpus is thinnest and reports half-yearly.
  • Only the model's error is measured, not the system's. The reproduction check measures the deterministic projection against reported history. There is no backtest of the full nine-lens pipeline, because doing it honestly needs point-in-time consensus and a corpus rebuilt per past quarter, and neither exists inside a one-day event.
  • The judge is a single point of judgement. One deep call per company: if it fails, the fallback is a median of surviving views, which is labelled degraded but is a materially weaker answer.
  • The corpus is frozen at 2026-08-14 and the run is 2026-08-16. The two-day gap is covered only by date-bounded web search, which feeds perception and reaches no revenue or margin driver by design.
  • The shape checker cannot judge quality. It verifies that the workbooks are exactly what the organisers asked for. Whether 47,320 is a good number for Home Depot is a question no check in this repository can answer.

How to reproduce the final run

Final commit: 52bb54d72389ef3a94ea798785e34f548a06c0d3

Final command: py -m forecaster.final_run

Expected output: four completed workbooks in submission/, one timestamped log in logs/, one results file per company under runs/, and exit code 0.

The log records the git commit and whether the working tree was clean, the as_of and corpus freeze dates, every stage event as it is emitted, the cost per company, the checker's verdict per file and the meaning of the exit code. Nothing under logs/ is ever overwritten, so a retry leaves the failed attempt exactly where it was.
